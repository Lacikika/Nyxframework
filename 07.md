# 📜 Part 7/10: Autonomous Civic Governance & Legislative Engine (`nyx_parliament`)

> **Spec Purpose:** Authoritative engine for democratic elections, ranked-choice ballot computations, bill formulation pipelines, and dynamic penal code synchronizations.
> 
> **Philosophy:** No hardcoded laws or staff-dictated legislation. Players draft statutes, vote on municipal initiatives, establish tax caps, and elect district representatives through tamper-proof ballot mechanics.
> 
>   

## 1. Governance Lifecycle & Democratic State Machine

```
   [Petition / Bill Proposal]
               │ (Signature Threshold Reached)
               ▼
   [Parliamentary / Ballot Cycle]
               │ (Ranked-Choice Ballot Engine)
               ▼
       [Vote Tabulation]
        ├── Passed ──> [Enact Law & Update Penal Schema Engine]
        └── Rejected ─> [Archive Bill & Return Collateral]
```

### 1.1 Ranked-Choice Voting (Instant-Runoff) Engine

Elections and citizen referendums do not use plurality voting (first-past-the-post), which fosters polarization and stagnation. The server processes ballots via an Instant-Runoff Voting (IRV) algorithm:

  

1. Ballots rank candidates or policy options from $1$ to $N$.
    
      
    
2. First-choice preferences are tabulated server-side.
    
      
    
3. If an option secures $> 50\%$ of active ballots, it is declared the winner.
    
      
    
4. If no option exceeds $50\%$:
    
      
    - The candidate/option with the fewest first-preference votes is eliminated.
        
          
        
    - Ballots assigned to the eliminated option transfer to their next available preference.
        
          
        
    - Recount repeats recursively until an option crosses the majority threshold.
        
          
        

## 2. Dynamic Law & Penal Code Synchronization

When legislation passes, the penal code is not manually updated in a document. The changes apply directly to the server's authoritative legal matrix, synchronizing in real time with the police Mobile Data Terminal (MDT), citation interfaces, and automated billing hooks.

  

### 2.1 The Dynamic Statute Model

- **Statutory Limits:** Every statute declares parameter ranges that the legislature may adjust:
    
      
    - Speed limits per zone classification (urban, highway, industrial).
        
          
        
    - Fine amount bounds ($[\text{MinFine}, \text{MaxFine}]$).
        
          
        
    - Maximum custodial sentence times ($[\text{MinMonths}, \text{MaxMonths}]$).
        
          
        
    - Sales tax percentage bounds ($[0\%, 15\%]$).
        
          
        
    - Commercial licensing fees and minimum business equity minimums.
        
          
        

## 3. Database Schema & Ballot Integrity

Ballot voting demands strict voter authentication while preserving ballot secrecy. Ballots separate the voter registry (proving participation) from the encrypted vote choice (preventing voter tracking).

  

### 3.1 SQL Migration Definition

SQL

-- Legislative sessions, referendums, and general elections
CREATE TABLE IF NOT EXISTS `nyx_parliament_sessions` (
  `session_id` VARCHAR(64) PRIMARY KEY, -- e.g., 'election:mayor:2026_q4', 'referendum:bill_42'
  `title` VARCHAR(128) NOT NULL,
  `description` TEXT NOT NULL,
  `type` ENUM('election', 'referendum', 'bill_vote') NOT NULL,

  `starts_at` TIMESTAMP NOT NULL,
  `ends_at` TIMESTAMP NOT NULL,
  `status` ENUM('scheduled', 'active', 'tallying', 'concluded', 'invalidated') DEFAULT 'scheduled',

-- Voter participation ledger (prevents duplicate voting and Sybil attacks)
CREATE TABLE IF NOT EXISTS `nyx_parliament_voter_registry` (
  `registry_id` BIGINT AUTO_INCREMENT PRIMARY KEY,
  `session_id` VARCHAR(64) NOT NULL,
  `hardware_hash` VARCHAR(64) NOT NULL,
  `voted_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY `unique_hardware_per_session` (`session_id`, `hardware_hash`),
  FOREIGN KEY (`session_id`) REFERENCES `nyx_parliament_sessions`(`session_id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- Anonymized ballot receipts (disconnected from citizen identity)
CREATE TABLE IF NOT EXISTS `nyx_parliament_ballots` (

  `session_id` VARCHAR(64) NOT NULL,
  `ballot_hash` VARCHAR(64) NOT NULL, -- Verification receipt given to player
  `preferences` JSON NOT NULL, -- Array of strings: ["candidate_a", "candidate_c", "candidate_b"]
  `submitted_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  INDEX `idx_session_ballots` (`session_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- Authoritative active penal and statutory laws
CREATE TABLE IF NOT EXISTS `nyx_parliament_laws` (
  `law_id` VARCHAR(32) PRIMARY KEY, -- e.g., 'penal:felony_speeding', 'tax:sales_rate'
  `title` VARCHAR(96) NOT NULL,
  `category` ENUM('penal_infraction', 'penal_misdemeanor', 'penal_felony', 'fiscal_policy', 'zoning') NOT NULL,
  `current_value` JSON NOT NULL, -- {"fine": 2500, "months": 15} or {"rate": 0.08}
  `min_allowed` JSON NOT NULL,
  `max_allowed` JSON NOT NULL,
  `last_amended_by_session` VARCHAR(64) NULL,
  `updated_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX `idx_law_cat` (`category`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

## 4. Server-Side Election Engine & Vote Verification

### 4.1 Ballot Submission Pipeline

```
Client Enters Physical Voting Booth (nyx_interact)
                         │
                         ▼
        [RPC: parliament:castBallot]
                         │
                         ▼
        [Server Evaluates Eligibility]
        ├── Check: Session status == 'active'
        ├── Check: Current time inside [starts_at, ends_at]
        └── Check: Voter Registry has no matching hardware_hash
                         │
                         ▼
        [Acquire Mutex & Commit Transaction]
        ├── Insert voter_registry row (Hardware Token Hash)
        ├── Insert anonymized ballot with unique receipt hash
        └── Emit verification receipt hash to client UI
                         │
                         ▼
        [Release Mutex & Notify UI: BALLOT_CAST_SUCCESS]
```

### 4.2 Tabulation Routine (IRV Algorithm)

Lua

```
-- server/tabulation.lua
Nyx = Nyx or {}
Nyx.Parliament = Nyx.Parliament or {}

function Nyx.Parliament.TabulateRankedChoice(sessionId)
    local ballotsRaw = MySQL.query.await([[
        SELECT preferences FROM nyx_parliament_ballots WHERE session_id = ?
    ]], { sessionId })

    local ballots = {}
    for _, b in ipairs(ballotsRaw) do
        table.insert(ballots, json.decode(b.preferences))
    end

    local totalBallots = #ballots
    if totalBallots == 0 then
        return nil, 'NO_BALLOTS_SUBMITTED'
    end

    local activeCandidates = {}
    for _, b in ipairs(ballots) do
        for _, candidate in ipairs(b) do
            activeCandidates[candidate] = true
        end
    end

    while true do
        local firstPrefs = {}
        for c, _ in pairs(activeCandidates) do firstPrefs[c] = 0 end

        for _, prefs in ipairs(ballots) do
            for _, candidate in ipairs(prefs) do
                if activeCandidates[candidate] then
                    firstPrefs[candidate] = firstPrefs[candidate] + 1
                    break
                end
            end
        end

        local majorityNeeded = math.floor(totalBallots / 2) + 1
        local lowestCandidate = nil
        local lowestVotes = math.huge

        for candidate, votes in pairs(firstPrefs) do
            if votes >= majorityNeeded then
                return candidate, firstPrefs -- Clear majority winner found
            end
            if votes < lowestVotes then
                lowestVotes = votes
                lowestCandidate = candidate
            end
        end

        -- Check for total tie / exhaustion
        local remainingCount = 0
        for _ in pairs(activeCandidates) do remainingCount = remainingCount + 1 end
        if remainingCount <= 2 then
            -- Highest of the last two wins
            local topCandidate = nil
            local maxV = -1
            for c, v in pairs(firstPrefs) do
                if v > maxV then maxV = v; topCandidate = c end
            end
            return topCandidate, firstPrefs
        end

        -- Eliminate lowest candidate and run subsequent iteration
        activeCandidates[lowestCandidate] = nil
    end
end
```

## 5. Legislative Bill Formulation & Auto-Execution

When elected officials author a bill, the submission payload contains structured modification instructions rather than plain text alone.

  

### 5.1 Bill Payload Format

JSON

```
{
  "sessionId": "bill:tax_reduction_2026",
  "title": "Municipal Commerce Stimulus Act",
  "proposerCitizenId": "NYX10248",
  "actions": [
    {
      "targetLawId": "tax:sales_rate",
      "field": "rate",
      "newValue": 0.05
    },
    {
      "targetLawId": "penal:commercial_fraud",
      "field": "fine",
      "newValue": 15000
    }
  ]
}
```

### 5.2 Auto-Enactment Hook

Upon passage and verification of a bill's vote outcome:

  

1. Server loads the `actions` array.
    
      
    
2. Validates each `newValue` against the `min_allowed` and `max_allowed` boundaries in `nyx_parliament_laws`.
    
      
    
3. Commits the updates inside a single database transaction.
    
      
    
4. Triggers server-wide sync event `nyx:parliament:lawsUpdated`.
    
      
    
5. `nyx_treasury` updates its active tax interceptor cache.
    
      
    
6. Police MDT modules read the modified maximum fines and prison bounds automatically.

## 8. Verification & Test Criteria

- [ ] **Instant-Runoff Precision:** Simulate an election with 3 candidates and 100 cast ballots where Candidate A gets $40\%$, Candidate B gets $35\%$, and Candidate C gets $25\%$. Confirm that Candidate C's second-preference distribution resolves the winner correctly without data loss.
    
      
    
- [ ] **Duplicate Vote Rejection:** Attempt to cast a second ballot during the same session using the same hardware/license hash; confirm transaction aborts with `ALREADY_VOTED` error.
    
      
    
- [ ] **Bounds Enforcement:** Submit a bill proposal attempting to set the sales tax rate to $25\%$; confirm the server rejects the proposal because it exceeds the `max_allowed` threshold ($15\%$).
    
      
    
- [ ] **Dynamic Tax Propagation:** Pass a bill reducing the sales tax rate from $8\%$ to $5\%$; verify that subsequent purchases processed by `nyx_treasury` deduct exactly $5\%$ at points of sale without restarting any resource.
