# ⚖️ Part 8/10: Decentralized Judiciary & Forensic Engine (`nyx_judiciary`)

> **Spec Purpose:** Authoritative legal processing, immutable forensic chain-of-custody tracking, dynamic warrant issuance, and automated civic jury selection.
> 
> **Philosophy:** No out-of-character staff arbitration for criminal disputes. Players execute investigations, collect physical evidence verified by cryptographic hashes, conduct trials in designated courtroom routing zones, and reach binding verdicts through peer juries.
> 
>   

## 1. Cryptographic Chain-of-Custody Model

Forensic evidence items (spent cartridge casings, blood splatters, gunpowder residue, vehicle paint chips) do not store static description text. Every piece of physical evidence generates a deterministic SHA-256 fingerprint at creation, binding the data to immutable server-side records.

  

```
       [Discharge / Trauma Event]
                   │
                   ▼
      [Generate Forensic Evidence]
    SHA-256(WeaponID + Coords + Timestamp)
                   │
                   ▼
       [Physical Collection by Player]
   ├── Handled with Latex Gloves ──> [Custody Chain Intact]
   └── Handled with Bare Hands   ──> [Chain Contaminated: Fingerprint Added]
                   │
                   ▼
        [Secure Evidence Locker]
   ├── Checked In by Officer
   └── Stored for Trial Docket
```

### 1.1 Hash Derivation Formula

$$\text{EvidenceHash} = \text{SHA-256}(\text{SourceSerial} \parallel \text{OriginCitizenID} \parallel \text{Coordinates} \parallel \text{Salt})$$

When an investigator submits evidence to a court docket:

  

- The defense counsel can query the evidence log verification endpoint.
    
      
    
- If any metadata field was altered manually or tampered with, the recomputed checksum fails, rendering the evidence inadmissible.

## 3. Automated Jury Summons & Routing Engine

To eliminate biased judgments and staff intervention, felony trials trigger an automated summons pipeline pulling active, impartial citizens from the server's live registry.

  

```
       [Docket Scheduled for Trial]
                   │
                   ▼
     [Query Active Unaffiliated Pool]
     ├── Filter: Exclude Police / EMS
     ├── Filter: Exclude Plaintiff & Defendant
     └── Filter: Exclude Close Org Associates
                   │
                   ▼
       [Issue Automated Summons]
    (Player Receives Subpoena Notification)
                   │
                   ▼
   [Summoned Juror Enters Courthouse]
                   │
                   ▼
  [Routed to Isolated Jury Box / Bucket]
```

### 3.1 Unbiased Juror Selection Routine

Lua

```
-- server/jury.lua
Nyx = Nyx or {}
Nyx.Judiciary = Nyx.Judiciary or {}

function Nyx.Judiciary.SummonJury(docketId, requiredCount)
    requiredCount = requiredCount or 5

    local docket = MySQL.single.await([[
        SELECT plaintiff_citizen_id, defendant_citizen_id FROM nyx_judiciary_dockets WHERE docket_id = ?
    ]], { docketId })

    if not docket then return false, 'DOCKET_NOT_FOUND' end

    -- Collect all active, online citizens
    local candidates = {}
    for source, player in pairs(Nyx.Players) do
        local citId = player.citizenId
        local job = player.metadata.job or 'unemployed'

        -- Exclude law enforcement, justice staff, and trial participants
        local isLawEnforcement = (job == 'police' or job == 'state_police' or job == 'doj')
        local isParticipant = (citId == docket.plaintiff_citizen_id or citId == docket.defendant_citizen_id)

        if not isLawEnforcement and not isParticipant then
            table.insert(candidates, { source = source, citizenId = citId })
        end
    end

    if #candidates < requiredCount then
        return false, 'INSUFFICIENT_CITIZENS_FOR_JURY'
    end

    -- Fisher-Yates shuffle for true random distribution
    for i = #candidates, 2, -1 do
        local j = math.random(i)
        candidates[i], candidates[j] = candidates[j], candidates[i]
    end

    local selected = {}
    for i = 1, requiredCount do
        local juror = candidates[i]
        table.insert(selected, juror)

        MySQL.insert.await([[
            INSERT INTO nyx_judiciary_juries (docket_id, citizen_id, selection_status)
            VALUES (?, ?, 'summoned')
        ]], { docketId, juror.citizenId })

        TriggerClientEvent('nyx:ui:notify', juror.source, {
            type = 'warning',
            title = 'CIVIC SUMMONS',
            message = ('You are summoned for jury duty on case %s. Report to District Court.'):format(docketId)
        })
    end

    return true, selected
end
```

## 4. Evidence Handling & Crime Scene Processing

### 4.1 Field Evidence Generation

When an action takes place (e.g., weapon discharge), the server generates a transient evidence node in memory:

  

Lua

```
-- server/evidence.lua
function Nyx.Judiciary.RegisterBallisticEvent(source, weaponHash, coords)
    local player = Nyx.Players[source]
    if not player then return end

    local serialNumber = player.metadata.equippedWeaponSerial or 'UNKNOWN'
    local salt = Nyx.Utils.GenerateSalt(8)
    
    local rawString = ('%s:%s:%.2f,%.2f,%.2f:%s'):format(
        serialNumber, player.citizenId, coords.x, coords.y, coords.z, salt
    )
    local hash = Nyx.Utils.Sha256(rawString)

    local dropId = Nyx.Utils.GenerateUUID()
    Nyx.Judiciary.ActiveCrimeScenes[dropId] = {
        evidenceId = dropId,
        type = 'casing',
        hash = hash,
        originCitizenId = player.citizenId,
        coords = coords,
        metadata = {
            weaponSerial = serialNumber,
            caliber = Nyx.Weapons.GetCaliber(weaponHash),
            salt = salt
        },
        expiresAt = os.time() + 3600 -- Disappears naturally after 1 hour if not collected
    }

    -- Stream localized marker to players holding forensic equipment
    Nyx.Judiciary.SyncEvidenceNearby(coords)
end
```

### 4.2 Collection Contamination Matrix

- **With Latex Gloves Equipped:** Evidence moves into an evidence bag container with `is_contaminated = 0`.
    
      
    
- **Without Gloves:** Evidence is flagged with `is_contaminated = 1` and `contamination_source = collectorCitizenId`. The forensic report marks the custody chain compromised.
    
      
    

## 5. Automatic Execution of Court Orders

Once a verdict is rendered (via jury majority or judicial bench decree), manual admin or police execution is not required. The framework automatically applies the judgment parameters:

  

1. **Monetary Fines & Restitution:**
    
      
    - Fines deduct automatically from the defendant's bank account via `nyx_treasury`.
        
          
        
    - The fine splits: civil restitution routes directly to the plaintiff; statutory penalties route to `account:gov:city:master`.
        
          
        
2. **Custodial Sentences:**
    
      
    - If the defendant is online and present in the courtroom, their ped transitions to the correctional routing bucket.
        
          
        
    - Prison sentence minutes commit to `nyx_characters.metadata.prisonSentence`.
        
          
        
3. **Warrant Invalidation:**
    
      
    - Active warrants associated with the docket automatically switch status to `executed`.
        
          
        

## 6. Network RPC Interface (`nyx_judiciary`)

|**RPC Route**|**Caller**|**Arguments**|**Data Returned / Action**|
|---|---|---|---|
|`judiciary:fileDocket`|Client|`title, defendantId, caseType, brief`|Creates new legal docket; returns `docketId`|
|`judiciary:collectEvidence`|Client|`evidenceId, useGloves`|Performs server distance check, generates hash, places item in inventory|
|`judiciary:verifyEvidence`|Client|`evidenceHash`|Recomputes metadata hash; verifies chain-of-custody integrity|
|`judiciary:issueWarrant`|Client|`targetId, type, causeSummary, expiry`|Validates judicial role token, commits warrant to public MDT registry|
|`judiciary:castJuryVote`|Client|`docketId, voteOutcome`|Confirms juror presence in jury box, stores anonymized vote|
|`judiciary:closeDocket`|Client|`docketId, verdictPayload`|Validates authority; triggers automated fine and sentencing pipeline|

## 8. Verification & Test Criteria

- [ ] **Forensic Hash Integrity:** Modify a ballistic record's serial number inside the database; execute `judiciary:verifyEvidence` and confirm the server flags the record as `HASH_MISMATCH_TAMPERED`.
    
      
    
- [ ] **Contamination Accuracy:** Collect blood evidence without gloves equipped; verify the created inventory item explicitly contains the collector's citizen ID inside the `contamination_source` metadata node.
    
      
    
- [ ] **Jury Summons Isolation:** Trigger a felony jury call with 5 active candidates; verify that candidates receive notifications, are assigned to the jury table, and none belong to the police or DOJ factions.
    
      
    
- [ ] **Automated Fine Execution:** Submit a guilty verdict on a civil suit awarding $\$25,000.00$ in damages; verify that the defendant's bank account drops by $\$25,000.00$, the plaintiff's account increases by $\$25,000.00$, and a transaction record logs inside `nyx_treasury_ledger`.
