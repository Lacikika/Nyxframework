# 🚀 SYSTEM PROMPT & SPECIFICATION: Nyxframework Engine Builder

> **To the Implementing AI / Engineer:**
> You are tasked with architecting and building **Nyxframework**, an ultra-optimized, modular, decentralized FiveM roleplay framework. This system is strictly designed around a **"run by the people, not for the people"** philosophy: eliminate static NPC-driven economies, staff-arbitrated civil systems, and centralized admin bottlenecks. Everything must flow through player-owned institutions, verifiable server-authoritative state, and zero-sum production pipelines.

---

## 🛠️ Global Technical Constraints & Rules

1. **Strict Server-Authoritative Architecture:**
   - The client is an input transmitter and render terminal.
   - All state mutations (inventories, balances, permissions, entity states) must be validated and executed server-side.
   - Zero trust in client-sent arguments (e.g., never accept item counts, prices, or coordinates blindly).

2. **Performance Budget ($0.00 - 0.01 ms baseline):**
   - No busy-wait client polling loops (`while true do Wait(0)` is forbidden unless bound to an active, localized render frame like scaleforms or targets).
   - Use event-driven hooks, state bags (`Entity(x).state`), and distance-based trigger zones (spatial partitioning / spatial grid).

3. **Database & Storage:**
   - Use `oxmysql` with async prepared queries and transactions for all mutations affecting money/inventory.
   - Hot state resides in server memory; batch-sync to the database on intervals, role swaps, and clean disconnects.
   - Implement idempotent schema migration scripts on startup (`nyx_core/migrations`).

4. **Codebase Standards:**
   - Modular, decoupled architecture (sub-resources communicate via clean RPCs and exports).
   - Unified logging and error boundaries with contextual breadcrumbs (player identifier, character ID, execution trace).


## 📋 Module Deep Dives & Action Items

### 1. nyx_core (Kernel & Identity)

- [ ] **Deferral Pipeline:** Authenticate incoming connections, match FiveM/license/Discord identifiers, check bans, and assign a clean temporary routing bucket.
- [ ] **Multi-Character Selection:** Transmit character summaries to `nyx_ui`; isolate character world entities until spawn point confirmation.
- [ ] **In-Memory Player Registry:**
    - Fast hash map: `Players[source] = { citizenId, charId, permissions, metadata, jobs, wallets }`.
    - Garbage-collect state cleanly upon `playerDropped`.
- [ ] **Bidirectional RPC Utility:**
    - Server-side: `Nyx.RPC.Register(name, handler)`
    - Client-side: `Nyx.RPC.Trigger(name, ...args): Promise<result>` with built-in execution timeouts (default: 5000ms).
### 2. nyx_inventory (State & Metadata Engine)

- [ ] **Schema Definition:**
    JSON ```
    {
      "itemId": "weapon_combatpistol",
      "slot": 1,
      "amount": 1,
      "metadata": {
        "serialNumber": "NYX-84920",
        "durability": 98.5,
        "components": ["suppressor", "extended_mag"]
      }
    }
- [ ] **Zero-Duplication Locking:** Lock inventory slots server-side during active transfers or trades; reject concurrent requests with explicit error codes.
- [ ] **Drop & Stash System:** Physical world drops represented by networked props with proximity-target hooks; persistent stashes tied to coordinates or property IDs.

### 3. nyx_treasury (Decentralized Public Finance)

- [ ] **Ledger Engine:** Dedicated ledger table logging all credits/debits with double-entry accounting checks:
$$\sum \text{Credits} = \sum \text{Debits}$$
    
- [ ] **Dynamic Tax Hooks:** Intercept all trade, store, and property transactions with an automated point-of-sale tax split.
- [ ] **Fiscal Circuit Protection:**
    - Calculate `CurrentReserve / TargetReserve` every in-game payroll cycle.
    - Automatically scale down civil service checks and disable high-cost public utilities when reserves hit critical levels.

### 4. nyx_logistics (Zero-Sum Supply Chain)

- [ ] **Finite Harvest Nodes:** Dynamic resource spawns with internal cool-downs and diminishing yields per extraction pass.
- [ ] **Assembly System:** Factory/workbench interfaces processing recipes ($A + B \rightarrow C$) with real-world time delays.
- [ ] **Retail Shelving Registry:** Stores are not vendor loops; they are read/write inventory containers. Zero stock means physical empty shelves and blocked transactions.
- [ ] **Dynamic Pricing Math:** Implement supply-vs-demand price scaling:
$$\text{Price} = \text{BasePrice} \times \left(1 + \frac{\text{TargetStock} - \text{CurrentStock}}{\text{TargetStock}}\right)$$


### 5. nyx_parliament & nyx_judiciary (Civic Engine)

- [ ] **Voting Engine:** Instant Runoff / Ranked Choice vote counter running server-side; identity hashing to enforce one vote per physical player per election.
- [ ] **Penal Code Integration:** Database-driven law parameters directly read by the police MDT and citation system.
- [ ] **Cryptographic Evidence Registry:** Weapon discharges and forensic traces generate unique hashed records verified on courtroom presentation.
- [ ] **Jury Pool Dispatcher:** Automated random selection and routing of active, non-affiliated players into an isolated jury box instance.
### 6. nyx_factions (Autonomous Collectives)

- [ ] **Charter Generation:** Player-created groups with dynamic database records, bypassing static config files or restart requirements.
- [ ] **RBAC Node Architecture:** Multi-tier permission strings (`funds:deposit`, `funds:withdraw`, `inventory:access`, `member:invite`).
- [ ] **Multi-Signature Vaults:** Require two or more authorized signatures via UI for expenditures exceeding a customizable threshold.

## 🎯 Implementation Directive for Next Phase
When instructed to begin coding:
1. **Start with `nyx_core`:** Deliver the foundation first—manifest, database connection wrapper, character deferral/loading handler, and the RPC communication layer.
2. **Follow with `nyx_inventory`:** Deliver the database schema, item definitions, and secure server-side transfer logic.
3. **Layer the Civic Modules:** Implement `nyx_treasury`, `nyx_logistics`, and `nyx_factions` using the core exports.
