# 🎒 Part 4/10: Storage & Item Engine (`nyx_inventory`)

> **Spec Purpose:** Authoritative state machine for physical containers, slot matrices, dynamic metadata degradation, and world entity drops.
> 
> **Security Target:** Zero client-side item calculation, zero duplicate vectors through atomic transaction locks, and deterministic serialization across crashes.
> 
>   

## 1. Database Schema & Storage Persistence

Inventories are decoupled from player accounts into discrete container records. A container can belong to an entity, a coordinate zone, a vehicle trunk, or an active player character.

  

### 1.1 SQL Migration Definition

SQL

```
-- Container definitions and maximum constraints
CREATE TABLE IF NOT EXISTS `nyx_inventories` (
  `id` VARCHAR(64) PRIMARY KEY, -- e.g. 'char:NYX10248:main', 'drop:UUID', 'trunk:PLATE123'
  `type` VARCHAR(24) NOT NULL,   -- 'player', 'drop', 'trunk', 'glovebox', 'stash'
  `max_weight` INT UNSIGNED NOT NULL DEFAULT 30000, -- in grams (30kg)
  `max_slots` SMALLINT UNSIGNED NOT NULL DEFAULT 40,
  `created_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  `updated_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX `idx_inv_type` (`type`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- Discrete items contained within an inventory
CREATE TABLE IF NOT EXISTS `nyx_inventory_items` (
  `item_uuid` VARCHAR(36) PRIMARY KEY,
  `inventory_id` VARCHAR(64) NOT NULL,
  `item_id` VARCHAR(64) NOT NULL,
  `slot` SMALLINT UNSIGNED NOT NULL,
  `amount` INT UNSIGNED NOT NULL DEFAULT 1,
  `metadata` JSON NOT NULL,
  `created_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (`inventory_id`) REFERENCES `nyx_inventories`(`id`) ON DELETE CASCADE,
  UNIQUE KEY `unique_slot_per_inv` (`inventory_id`, `slot`),
  INDEX `idx_item_id` (`item_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 2. Server-Side Memory Cache & Concurrency Control

Inventories are loaded into server memory upon interaction and synced asynchronously. All write operations pass through a single-thread mutex queue per inventory to eliminate race conditions.

  

```
Incoming Client Action (Move / Split / Give)
                 │
                 ▼
         [Check Inventory Mutex]
                 │
        ┌────────┴────────┐
   [Locked]           [Free]
        │                 │
        ▼                 ▼
[Drop Action]     [Acquire Mutex Lock]
(Return Error)            │
                          ▼
                  [Validate Weight & Slots]
                          │
                          ▼
                  [Mutate In-Memory State]
                          │
                          ▼
                  [Broadcast Delta to Listeners]
                          │
                          ▼
                  [Release Mutex Lock]
                          │
                          ▼
                  [Queue Async SQL Sync]
```

### 2.1 Mutex Lock Specification

- Every inventory has an active lock state: `Nyx.Inventory.Locks[invId] = os.time() + 2`.
    
      
    
- Lock timeout defaults to $2000\text{ ms}$. If an unhandled thread exception occurs, the lock automatically expires to prevent permanently frozen slots.
    
      
    
- Mutex lock covers **both** the origin and destination containers during cross-inventory transfers.

### 3.2 Decay & Degradation Cycle

- Item degradation is calculated upon access and periodically processed via an internal tick:
    
      
    
    $$\text{CurrentDurability} = \max\left(0, \; \text{InitialDurability} - (\Delta t \times \text{DecayRate})\right)$$
    
- When durability reaches $0$, weapons experience frequent firing jams or become completely inoperable, and perishable consumables transition to an inedible spoiled state.

## 5. Network RPC Interface (`nyx_inventory`)

The client never commands the server to "give item" or "delete item". The client strictly requests an operational delta between two slots.

  

### 5.1 Protocol Routes

|**RPC Route**|**Caller**|**Arguments**|**Validation Checks**|
|---|---|---|---|
|`inventory:moveSlot`|Client|`fromInv, toInv, fromSlot, toSlot, amount`|Ownership, slot bounds, weight limit, mutex state|
|`inventory:useItem`|Client|`invId, slot`|Durability $> 0$, player not incapacitated, cooldown passed|
|`inventory:dropItem`|Client|`invId, slot, amount`|Player proximity to target coordinates, valid ground collision|
|`inventory:openContainer`|Client|`targetInvId`|Proximity check, vehicle locked status, property authorization|

### 5.2 Server Action Handler Blueprint

Lua

```
-- Conceptual server-side slot swap transaction
Nyx.RPC.Register('inventory:moveSlot', function(source, payload)
    local srcInv = payload.fromInv
    local dstInv = payload.toInv
    local srcSlot = payload.fromSlot
    local dstSlot = payload.toSlot
    local amount = payload.amount

    if not Nyx.Inventory.ValidateAccess(source, srcInv) or not Nyx.Inventory.ValidateAccess(source, dstInv) then
        return { success = false, error = 'PERMISSION_DENIED' }
    end

    if not Nyx.Inventory.AcquireLock(srcInv) or not Nyx.Inventory.AcquireLock(dstInv) then
        return { success = false, error = 'CONTAINER_BUSY' }
    end

    local result = Nyx.Inventory.ProcessMove(srcInv, dstInv, srcSlot, dstSlot, amount)

    Nyx.Inventory.ReleaseLock(srcInv)
    Nyx.Inventory.ReleaseLock(dstInv)

    return result
end)
```

## 6. Physical Ground Drops & World Interactivity

### 6.1 Entity Culling & Spatial Grid

- Drops are not persistent GTA entities spawned at infinite range.
    
      
    
- The server maintains a spatial coordinate hash of active ground drops:
    
    `SpatialDrops[zoneKey] = { dropId, coords, itemSummary }`
    
      
    
- When a client enters a active zone (within $25.0\text{ units}$), the server transmits the drop list.
    
      
    
- The client registers a single raycast interaction point via `nyx_interact` to display the ground loot bag or prop.
    
      
    
- If the drop is emptied, the server automatically broadcasts an entity deletion call to all clients in the zone and clears the container from the database.

## 8. Verification & Test Criteria

- [ ] **Duplication Edge Case:** Set up two client instances attempting to drag the exact same item from a shared stash at identical microsecond intervals; confirm only one transaction resolves while the other returns `CONTAINER_BUSY`.
    
      
    
- [ ] **Weight Boundary Enforcement:** Attempt to place $30.1\text{ kg}$ into a $30.0\text{ kg}$ trunk container; verify transaction rejects server-side and client inventory renders reset to source state.
    
      
    
- [ ] **Drop Persistence:** Drop an item on the ground, restart the `nyx_inventory` resource, and verify the ground container re-registers at the exact world coordinates with all dynamic metadata intact.
