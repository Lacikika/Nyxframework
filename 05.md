# 🏛️ Part 5/10: Decentralized Public Finance & Ledger Engine (`nyx_treasury`)

> **Spec Purpose:** Authoritative double-entry municipal accounting, point-of-sale tax routing, public fund allocations, and autonomous fiscal crisis handling.
> 
> **Philosophy:** No magic server money pools. Public wages, infrastructure upkeep, and municipal services rely directly on collected sales, property, and licensing taxes.
> 
>   

## 1. Mathematical Model & Economic Balancing

### 1.1 The Closed-Loop Conservation Law

Every unit of currency within the public sphere must satisfy strict conservation. Under no condition does an automated system credit a balance without an explicit source debit:

  

$$\Delta M_{\text{Treasury}} = \sum (\text{Taxes} + \text{Fines} + \text{Fees}) - \sum (\text{Payrolls} + \text{Upkeep} + \text{Grants})$$

### 1.2 Dynamic Tax Interception Formula

Transactions passing through certified points of sale (retail registers, property deeds, wholesale trades, player-to-player corporate invoices) undergo an atomic tax split:

  

$$A_{\text{net}} = A_{\text{gross}} \times (1 - r_{\text{tax}})$$

$$A_{\text{tax}} = A_{\text{gross}} \times r_{\text{tax}}$$

Where $r_{\text{tax}}$ is the legally ratified sales tax rate ($0.00 \le r_{\text{tax}} \le 0.15$), managed dynamically by `nyx_parliament`.

  

### 1.3 Adaptive Wage Scaling (Fiscal Crisis Safeguard)

When the active balance of the municipal treasury ($B_{\text{current}}$) drops below the target operating reserve ($R_{\text{target}}$), public payroll payouts (police, EMS, public works, civic administration) scale down logarithmically to protect liquidity:

  

$$\text{PayoutMultiplier} = \begin{cases} 1.0 & \text{if } B_{\text{current}} \ge R_{\text{target}} \\ \max\left(0.10, \; \frac{\ln(B_{\text{current}} + 1)}{\ln(R_{\text{target}} + 1)}\right) & \text{if } B_{\text{crit}} \le B_{\text{current}} < R_{\text{target}} \\ 0.0 & \text{if } B_{\text{current}} < B_{\text{crit}} \end{cases}$$

When $B_{\text{current}} < B_{\text{crit}}$, public payrolls freeze, and infrastructure modules enter emergency degradation mode.

  

## 2. Database Schema & Double-Entry Ledger

All operations write to an append-only transaction ledger. Balance mutations are materialized in `nyx_accounts_balance` tables while remaining fully reconstructible from history.

  

### 2.1 SQL Migration Definition

SQL

```
-- Municipal and organizational bank accounts
CREATE TABLE IF NOT EXISTS `nyx_treasury_accounts` (
  `account_id` VARCHAR(64) PRIMARY KEY, -- e.g., 'gov:city:master', 'gov:dept:police', 'gov:dept:ems'
  `label` VARCHAR(96) NOT NULL,
  `balance` DECIMAL(15, 2) NOT NULL DEFAULT 0.00,
  `type` ENUM('public_master', 'department', 'reserve', 'grant_pool') NOT NULL,
  `signatories_required` TINYINT UNSIGNED NOT NULL DEFAULT 1,
  `created_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  INDEX `idx_acc_type` (`type`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- Append-only double-entry transaction ledger
CREATE TABLE IF NOT EXISTS `nyx_treasury_ledger` (
  `entry_id` BIGINT AUTO_INCREMENT PRIMARY KEY,
  `transaction_uuid` VARCHAR(36) NOT NULL,
  `debit_account` VARCHAR(64) NOT NULL,
  `credit_account` VARCHAR(64) NOT NULL,
  `amount` DECIMAL(15, 2) NOT NULL,
  `tax_deducted` DECIMAL(15, 2) NOT NULL DEFAULT 0.00,
  `category` VARCHAR(48) NOT NULL, -- 'payroll', 'pos_tax', 'property_tax', 'fine', 'infrastructure'
  `authorized_by` VARCHAR(64) NOT NULL, -- citizenId, 'SYSTEM', or 'ELECTION_BOARD'
  `memo` VARCHAR(255) NULL,
  `created_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  INDEX `idx_tx_uuid` (`transaction_uuid`),
  INDEX `idx_debit` (`debit_account`),
  INDEX `idx_credit` (`credit_account`),
  INDEX `idx_cat_created` (`category`, `created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- Budget allocation schedules voted by elected councils
CREATE TABLE IF NOT EXISTS `nyx_treasury_allocations` (
  `allocation_id` INT AUTO_INCREMENT PRIMARY KEY,
  `target_department` VARCHAR(64) NOT NULL,
  `percentage_split` DECIMAL(5, 2) NOT NULL, -- e.g., 40.00 (%)
  `cap_limit` DECIMAL(15, 2) NULL,
  `ratified_by_bill_id` VARCHAR(32) NOT NULL,
  `updated_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  FOREIGN KEY (`target_department`) REFERENCES `nyx_treasury_accounts`(`account_id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 3. Server-Side Accounting Engine

### 3.1 Ledger Execution Pipeline

```
Incoming Mutation Request (Transfer / POS Tax / Wage Flush)
                         │
                         ▼
        [Verify Ledger Mutex Lock]
                         │
                         ▼
        [Validate Account Liquidity (Debit >= Amount)]
                         │
                         ▼
        [Generate Transaction UUIDv4]
                         │
                         ▼
        [Execute Transactional SQL Block]
        ├── Write: Append nyx_treasury_ledger entry
        ├── Update: Decrement Debit Account Balance
        └── Update: Increment Credit Account Balance
                         │
                         ▼
        [Update Server Memory Cache State]
                         │
                         ▼
        [Emit WebSocket / NetEvent to Transparency UI]
```

### 3.2 Authoritative Transaction Processor

Lua

```
-- server/ledger.lua
Nyx = Nyx or {}
Nyx.Treasury = Nyx.Treasury or {}

function Nyx.Treasury.ExecuteTransfer(debitAcc, creditAcc, amount, category, authorizedBy, memo)
    if amount <= 0 then
        return false, 'INVALID_AMOUNT'
    end

    local txUuid = Nyx.Utils.GenerateUUID()

    local success = MySQL.transaction.await({
        {
            query = [[
                UPDATE nyx_treasury_accounts 
                SET balance = balance - ? 
                WHERE account_id = ? AND balance >= ?
            ]],
            values = { amount, debitAcc, amount }
        },
        {
            query = [[
                UPDATE nyx_treasury_accounts 
                SET balance = balance + ? 
                WHERE account_id = ?
            ]],
            values = { amount, creditAcc }
        },
        {
            query = [[
                INSERT INTO nyx_treasury_ledger 
                (transaction_uuid, debit_account, credit_account, amount, category, authorized_by, memo) 
                VALUES (?, ?, ?, ?, ?, ?, ?)
            ]],
            values = { txUuid, debitAcc, creditAcc, amount, category, authorizedBy, memo }
        }
    })

    if not success then
        return false, 'INSUFFICIENT_FUNDS_OR_LOCK_FAILURE'
    end

    Nyx.Treasury.SyncCache(debitAcc)
    Nyx.Treasury.SyncCache(creditAcc)
    Nyx.Treasury.BroadcastLedgerUpdate(txUuid)

    return true, txUuid
end
```

## 4. Public Service Payroll Engine

Payrolls do not pull from thin air. Every payout cycle traverses the municipal allocations table, pulls from funded departmental accounts, and throttles payouts automatically if the account hits critical limits.

  

### 4.1 Payroll Dispatch Routine

Lua

```
-- server/payroll.lua
function Nyx.Treasury.ProcessPublicPayroll()
    local masterReserve = Nyx.Treasury.GetBalance('gov:city:master')
    local targetReserve = Nyx.Config.Treasury.TargetReserve
    local critReserve = Nyx.Config.Treasury.CriticalReserve

    local multiplier = 1.0
    if masterReserve < targetReserve then
        if masterReserve <= critReserve then
            multiplier = 0.0
        else
            multiplier = math.max(0.10, math.log(masterReserve + 1) / math.log(targetReserve + 1))
        end
    end

    local activeEmployees = Nyx.Jobs.GetActiveDutyWorkers()

    for _, worker in ipairs(activeEmployees) do
        local baseWage = worker.gradeWage
        local payable = math.floor(baseWage * multiplier * 100) / 100
        local deptAccount = worker.deptAccount

        if payable > 0 then
            local success, txId = Nyx.Treasury.ExecuteTransfer(
                deptAccount,
                worker.bankAccount,
                payable,
                'payroll',
                'SYSTEM',
                ('Duty paycheck for %s (scale: %.2f)'):format(worker.citizenId, multiplier)
            )

            if success then
                TriggerClientEvent('nyx:ui:notify', worker.source, {
                    type = 'info',
                    message = ('Paycheck received: $%s (Wage Scale: %d%%)'):format(payable, math.floor(multiplier * 100))
                })
            else
                TriggerClientEvent('nyx:ui:notify', worker.source, {
                    type = 'warning',
                    message = 'Department payroll failed: Insufficient department funds.'
                })
            end
        else
            TriggerClientEvent('nyx:ui:notify', worker.source, {
                type = 'error',
                message = 'Municipal fiscal crisis: Public paychecks suspended.'
            })
        end
    end
end
```

## 7. Verification & Test Criteria

- [ ] **Conservation Balance Check:** Run 1,000 automated transactions across 5 sub-accounts; assert $\sum \text{LedgerDebits} \equiv \sum \text{LedgerCredits}$.
    
      
    
- [ ] **Overdraw Protection:** Attempt to debit $\$100,001.00$ from an account with $\$100,000.00$; verify the database update statement returns 0 rows affected, the transaction rolls back, and error `INSUFFICIENT_FUNDS` is returned.
    
      
    
- [ ] **Fiscal Crisis Degradation:** Manually drain the `gov:city:master` account to $\$0.00$; verify the next payroll cycle distributes $\$0.00$ to all on-duty personnel, and triggers state alerts across all connected terminals.
