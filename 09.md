# 🏢 Part 9/10: Autonomous Player Organizations & Multi-Sig Vaults (`nyx_factions`)

> **Spec Purpose:** Authoritative engine for player-founded corporations, trade unions, cartels, cooperatives, granular node permissions, and cryptographic multi-signature corporate vaults.
> 
> **Philosophy:** Zero out-of-character staff ticket approvals for business creation. Players draft legal charters, pool private seed capital, purchase commercial real estate, assign fine-grained operational roles, and manage shared treasuries with on-chain cryptographic safety checks.
> 
>   

## 1. Autonomous Organization Lifecycle

```
    [Founders Draft Charter Document]
                   │
                   ▼
  [Deposit Seed Capital & Filing Fee]
   (Auto-Debited to Municipal Treasury)
                   │
                   ▼
  [Verify Minimum Signature Threshold]
   (≥ 3 Founding Citizens Sign at Terminal)
                   │
                   ▼
   [Autonomous Corporate Entity Formed]
  ├── Dynamic Database Registry Entry Created
  ├── Corporate Bank Account Spawned (`nyx_treasury`)
  ├── Master Warehouse / Stash Container Bound (`nyx_inventory`)
  └── Granular Role-Based Access Control (RBAC) Node Tree Initialized
```

## 2. Granular Role-Based Access Control (RBAC)

Organizations do not rely on fixed numerical rank tiers ($0$ to $5$). Access is determined by a bitwise or string-indexed permission node matrix:

  

### 2.1 Standard Permission Nodes

Plaintext

```
treasury:view_ledger       # Read real-time balance sheets and statement histories
treasury:deposit           # Deposit capital into organizational accounts
treasury:withdraw_low      # Withdraw funds below the multi-sig approval threshold
treasury:withdraw_high     # Initiate high-tier withdrawals requiring multi-sig confirmation
treasury:sign_tx           # Act as a certified signatory on multi-sig withdrawal requests
inventory:view             # Inspect contents of company stashes and warehouses
inventory:deposit          # Add items, materials, and crates to shared storage
inventory:withdraw         # Extract items and materials from shared storage
fleet:spawn                # Pull company-registered utility vehicles from commercial depot
fleet:manage               # Buy, sell, or assign company vehicle registrations
property:manage            # Modify door locks, security cameras, and workstation access
roster:invite              # Issue binding employment contracts to prospective members
roster:promote             # Adjust subordinate permission nodes and title designations
roster:terminate           # Revoke employment contracts and reclaim property keys
governance:call_vote       # Initiate an internal organizational referendum or board vote
```

## 4. Multi-Signature Treasury Safety Engine

To prevent insider embezzlements, rogue executives, or compromised client accounts from wiping company capital, large withdrawals route through an authoritative multi-signature approval queue.

  

```
       [Player Requests Large Withdrawal]
        (Amount > multisig_threshold_amount)
                         │
                         ▼
        [Server Evaluates Permission Node]
        (Check: member has 'treasury:withdraw_high')
                         │
                         ▼
        [Generate Multi-Sig Request Entry]
        ├── Lock requested funds in Escrow Sub-State
        ├── Transmit push notification to certified signatories
        └── Set expiration timer (48 hours)
                         │
                         ▼
        [Signatories Sign via Banking NUI]
        ├── Check: signatory has 'treasury:sign_tx'
        └── Append citizen ID to signature array
                         │
                         ▼
     [Signatures Reached == Required Threshold?]
        ├── YES: Release escrow funds & execute ledger transfer via nyx_treasury
        └── NO:  Remain pending until quorum or expiration timeout
```

### 4.1 Multi-Sig Verification Handler

Lua

```
-- server/multisig.lua
Nyx = Nyx or {}
Nyx.Factions = Nyx.Factions or {}

function Nyx.Factions.ApproveMultiSigRequest(source, requestId)
    local player = Nyx.Players[source]
    if not player then return false, 'INVALID_SESSION' end

    local req = MySQL.single.await([[
        SELECT r.*, f.treasury_account_id 
        FROM nyx_factions_multisig_queue r
        JOIN nyx_factions_registry f ON r.faction_id = f.faction_id
        WHERE r.request_id = ? AND r.status = 'pending'
    ]], { requestId })

    if not req then return false, 'REQUEST_NOT_FOUND_OR_RESOLVED' end

    if os.time() > math.floor(req.expires_at / 1000) then
        MySQL.query.await([[UPDATE nyx_factions_multisig_queue SET status = 'expired' WHERE request_id = ?]], { requestId })
        return false, 'REQUEST_EXPIRED'
    end

    -- Verify signatory permission
    if not Nyx.Factions.HasPermission(player.citizenId, req.faction_id, 'treasury:sign_tx') then
        return false, 'INSUFFICIENT_SIGNATORY_PRIVILEGES'
    end

    local signatures = json.decode(req.current_signatures) or {}

    -- Check for duplicate signing attempt
    for _, signerId in ipairs(signatures) do
        if signerId == player.citizenId then
            return false, 'ALREADY_SIGNED'
        end
    end

    table.insert(signatures, player.citizenId)

    if #signatures >= req.required_signatures then
        -- Threshold satisfied: execute authoritative transfer
        local success, txId = Nyx.Treasury.ExecuteTransfer(
            req.treasury_account_id,
            req.target_account,
            req.amount,
            'factions_multisig',
            ('MULTISIG:%s'):format(requestId),
            req.reason
        )

        if success then
            MySQL.query.await([[
                UPDATE nyx_factions_multisig_queue 
                SET current_signatures = ?, status = 'approved' 
                WHERE request_id = ?
            ]], { json.encode(signatures), requestId })

            Nyx.Factions.NotifyMembers(req.faction_id, ('Multi-Sig transfer of $%s approved and disbursed.'):format(req.amount))
            return true, 'DISBURSED'
        else
            return false, 'TREASURY_TRANSFER_FAILED'
        end
    else
        -- Update state with newly appended signature
        MySQL.query.await([[
            UPDATE nyx_factions_multisig_queue 
            SET current_signatures = ? 
            WHERE request_id = ?
        ]], { json.encode(signatures), requestId })

        return true, 'SIGNATURE_REGISTERED'
    end
end
```

## 5. Automated Dividend & Equity Distribution Engine

Organizations structured as cooperatives or equity partnerships distribute profits to stakeholders automatically without manual bookkeeping.

  

### 5.1 Equity Distribution Formula

At the end of an operational cycle (weekly or monthly):

  

$$\text{RetainedEarnings} = \text{NetProfits} \times (1 - r_{\text{reinvest}})$$

$$\text{Payout}_{i} = \text{RetainedEarnings} \times \left(\frac{S_i}{S_{\text{total}}}\right)$$

Where:

  

- $r_{\text{reinvest}}$ = Mandated capital reserve reinvestment percentage ($0.10 \le r_{\text{reinvest}} \le 0.50$).
    
      
    
- $S_i$ = Equity shares owned by citizen $i$.
    
      
    
- $S_{\text{total}}$ = Total issued organizational equity shares ($\sum S_i \equiv 100.00\%$).
    
      
    

All dividend splits write double-entry receipts directly to `nyx_treasury_ledger`, deducting from the corporate account and funding individual personal accounts.

  

## 6. Commercial Fleet Management & Tracking

Company vehicles belong to the legal entity, not to personal character identities.

  

### 6.1 Fleet Lifecycle Logic

1. **Spawn Authorization:** Any member with `fleet:spawn` can check out an idle vehicle from an authorized commercial parking depot.
    
      
    
2. **Access Control:** Company vehicles unlock via RFID proximity tokens granted to active organization members; no physical ignition hotwiring is required for authorized personnel.
    
      
    
3. **Condition Serialization:** When a commercial vehicle returns to a depot:
    
      
    - Body deformation, mechanical engine damage, tire wear, and remaining fuel levels commit directly to `nyx_factions_fleet.condition_data`.
        
          
        
    - The vehicle status returns to `stored`.

## 9. Verification & Test Criteria

- [ ] **Multi-Sig Execution Boundary:** Submit a withdrawal request of $\$100,000.00$ with a threshold set to $\$50,000.00$; verify that funds are not immediately moved, and an entry appears in `nyx_factions_multisig_queue`.
    
      
    
- [ ] **Quorum Authorization:** Have Signatory 1 sign the multi-sig request; verify the status remains `pending`. Have Signatory 2 sign; verify the status transitions to `approved`, the funds move via `nyx_treasury`, and both parties receive push confirmation.
    
      
    
- [ ] **RBAC Node Enforcement:** Attempt to spawn a commercial vehicle using a member account stripped of the `fleet:spawn` permission node; confirm the RPC returns `INSUFFICIENT_PERMISSIONS` and no entity is spawned.
    
      
    
- [ ] **Automated Dividend Split:** Configure an organization with 3 partners owning $50\%$, $30\%$, and $20\%$ equity shares; trigger an automated dividend payout of $\$10,000.00$ profit; verify that personal accounts are credited exactly $\$5,000.00$, $\$3,000.00$, and $\$2,000.00$ with zero fractional unit leakage.
